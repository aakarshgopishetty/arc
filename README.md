# ARC — handoff state

Everything below was done in this session. Two things changed: Gemini function
calling was wired up end to end, and the Capacitor Android project was
actually generated (not just planned).

## 1. Gemini function calling (new)

`api/gemini.js` now declares nine tools mirroring ARC's local skills
(`set_reminder`, `set_alarm`, `set_timer`, `list_reminders`,
`clear_reminders`, `add_note`, `list_notes`, `open_site`, `calculate`). The
regex matcher in `tryLocalSkill()` still runs first and handles anything it
already handled — function calling is only a fallback for phrasing that
doesn't match those patterns (e.g. "remind me to call mom sometime after my
3pm meeting").

Flow:
1. `index.html` posts the user's message plus `nowISO`/`tzOffsetMinutes` (so
   Gemini can compute absolute timestamps) to `/api/gemini`.
2. If Gemini decides to call one or more tools, the endpoint returns
   `{ functionCalls, modelTurnParts }` instead of `{ reply }`.
3. `index.html`'s new `executeFunctionCall()` runs the matching action
   locally (same functions the regex path uses — refactored out as
   `actionSetReminder`, `actionSetTimer`, etc., so there's one source of
   truth for each skill).
4. `index.html` re-POSTs with `functionResults` + `modelTurnParts` (and no
   `message`); the endpoint reconstructs the conversation as a `function`-role
   turn and asks Gemini for the final spoken reply.
5. If that follow-up call fails, ARC still reports the action succeeded
   locally (it already ran) rather than silently losing it.

**Not yet tested against the live API** — this sandbox can't reach
`generativelanguage.googleapis.com`, so the request/response shape (the
`function` role, `functionCall`/`functionResponse` part names, `OBJECT`/
`STRING` schema casing) is per Google's documented format but unverified
here. First real test should be a simple one ("remind me to stretch in five
minutes, phrased weirdly enough to dodge the regex") with your Vercel logs
open so you can see the raw Gemini response if anything's off.

## 2. Capacitor Android wrap (scaffolded)

- `www/` created with `index.html`, `manifest.json`, `sw.js`, `icons/`
  (mirrors repo root — Vercel keeps deploying from the root unchanged).
- `capacitor.config.json` — app id `com.aakarsh.arc`, `webDir: www`.
- `package.json` — `@capacitor/core`, `@capacitor/local-notifications`,
  `@capacitor/android`, `@capacitor/cli`.
- `npm install`, `npx cap add android`, and `npx cap sync android` were all
  actually run here — the `android/` folder in this zip is a real generated
  Capacitor Android Studio project, not just instructions. `node_modules/`
  and Gradle's build caches were stripped before zipping (large, and
  regenerated by the next two commands anyway).

**Remaining steps, on a machine with Android Studio + JDK:**
1. `npm install` (regenerates `node_modules/`)
2. `npx cap sync android` (harmless to re-run — re-copies `www/` and confirms
   the plugin is registered)
3. `npx cap open android` → build/run on a device or emulator
4. Grant the notification permission when prompted
5. Set a reminder, fully close the app, confirm it still fires
6. Optional: `capacitor.config.json` references a custom notification icon
   (`ic_stat_arc`) that doesn't exist yet — Android Studio's Image Asset tool
   (right-click `res` → New → Image Asset → Notification Icon) can generate
   it, or just delete the `smallIcon`/`iconColor` lines from
   `capacitor.config.json` to use the default app icon instead.
